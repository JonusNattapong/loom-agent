# Loom V1.1 planning note

V1.1 is the reliable distribution and unified execution milestone. It makes
the V1 public contract usable by consumers and keeps foreground, daemon, and
remote execution on the same policy and recovery path.

## Included

- Public workspace packages are versioned together and contain publish metadata.
- Public package manifests use registry-compatible dependencies rather than
  workspace-local `file:` references.
- Process recovery tests use file URLs and control messages that work on Windows
  as well as POSIX hosts.
- CI verifies build and tests on Ubuntu and Windows with Node 22 and 24.
- SDK daemon execution exposes the registered tool definitions and routes tool
  calls through the same durable `ToolExecutor` policy as embedded execution.

## Still intentionally out of scope

V1.1 does not add multi-controller HA, distributed consensus or storage,
mesh/P2P networking, NAT traversal, or universal exactly-once external side
effects. Those require a separate distributed-systems milestone.

## Release gate

Before publishing, run `npm ci`, `npm run build`, `npm test`, `npm run eval`,
and package smoke tests from a clean checkout. The package graph must be
published together so `@loom/sdk` and `@loom/cli` resolve their `1.1.x`
dependencies from the registry.
